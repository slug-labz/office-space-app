# Tasks — Office Space

Live task list for the app itself. Every task has an owner and a VERIFY condition. A task is
done when the VERIFY passes, not when someone says it is. (The office's own harness reads
`projects/<name>/TASKS.md`; this file is the repository's.)

**VERIFY is a command, not a verdict.** Write what should be run, in backticks: `` `npm test` exits 0 ``.
`/verify` runs the first backticked command and reports what happened. If a task genuinely
cannot be checked by a command, say so in plain words with **no backticks** — *reviewed by eye* —
so it is counted as uncheckable rather than quietly counted as passed.

**How the PR rows work.** An open PR's VERIFY is the command to run on `dev` once it has merged.
Where a PR only adds cases to a test file that already exists, that command passes before the
merge too. So a PR row moves to Done only when the PR has merged **and** its command passes on
the merged `dev`. GitHub Actions runs again (D25 in [DECISIONS.md](DECISIONS.md)), so a PR
merges on a passing `checks` run for the exact head being merged, as it did before D15.

Owners are sessions. *Review session* is the session that coordinates reviews and the merge
train, and its background agents. *Stale-pushes session* and *doc session* are the sessions
named "Stop stale approval pushes hiding or reviving held calls" and "Reattach doc comments that
drifted off their functions". Teammate 3's session has ended, and the review session carries
its PRs. Dates are UTC.
